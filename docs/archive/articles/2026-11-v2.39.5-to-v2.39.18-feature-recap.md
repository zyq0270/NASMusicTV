# 57 座城市、70 种转场、6 个视觉世界：一个开源 TV 音乐播放器的三周迭代实录

> 写在前面：NASMusicTV 是一款开源的音乐播放器，一个 APK 同时适配电视（遥控器）和手机（触屏），聚合 Jellyfin / Navidrome / 飞牛等 NAS 音源、网络音乐、百度网盘和本地音乐。从 2026 年 10 月 21 日到 11 月 10 日，它的版本号从 v2.39.5 一路走到 v2.39.18——**三周、14 个版本**，是这个项目迭代最密集的一段。这篇按主题盘点这三周到底加了什么，而不是把 CHANGELOG 抄一遍。项目地址见文末。

## 一、视觉世界大爆发：一次加了六个新场景

这三周最直观的变化，是全屏可视化从"频谱特效"升级成了"视觉世界"。产品主页把这六个新场景单列出来，我把它们的来历串一下：

**① 像素城市（v2.39.7 → v2.39.10 定稿）——57 座城。** 这是最耗工程量一个：开普敦、重庆、台北、大阪……一直堆到 57 座，每座城有自己的天气与时段（雨夜的东京、雪中的圣诞市集、亡灵节的墨西哥城）。换城逻辑也改了三遍：最早每 20 分钟定时切，后来改成**换歌曲时切换**并配全屏地球过场，最后改成洗牌式——所有城市轮一遍才重复。播放时右下角显示城市名、标语和当地实时时间。因上游素材版权原因，GitHub 公开构建版默认不含这个效果。

**② 旷野公路（v2.39.10 → v2.39.15 定稿）——原生 OpenGL ES 的夜路。** 地形、天空、雾、沿路三层 LOD、自动驾驶相机、路面白线、植被，后面又补了星球场景、水面、12 种上游路牌、金属护栏与桥、反光片。最折腾的是天空：v2.39.15 一天之内连改十几条，围绕云与天色在地平线处的接缝反复重写——云带被 mipmap 抹平、地平线露出纯色板、死 uniform 上传空转，最后才定稿。同样属于公开构建默认不含的实验性效果。

**③ 千里江山（v2.39.11 → v2.39.12）——水墨长卷。** 八层合成（绢底天幕 / 远景 / 中景主山 / 轮廓光 / 近景 / 江水 / 光尘 / 印章），无限滚动，低频推雾与江水、中频推轮廓光、高频推光尘。有个好玩的细节：右上角那枚篆字印章刻的是「扫地老师」。v2.39.12 做了一次**推翻重来**——放弃自创的光尘、做旧、呼吸缩放，改成忠于上游的绢白纸底 + 线描山体 + 单一世界空间，并补移植了上游的楼阁塔桥、五种树形、扁舟与人物。

**④ 歌词舞台（v2.39.13）——一个主题五个子模式。** 歌词点阵 / 逐字行光 / 全屏纵览 / 倾斜律动 / 分栏引导，遥控器上下键或手机上下滑动切换，选择持久化到切歌之后。这一版同时移除了三个老效果（心跳、反馈残像、歌词点阵），把歌词点阵并进了舞台的子模式 0。

**⑤ 生态地球（v2.39.14）——150 棵树、19 只动物。** 山脉、龙卷风、三层云、极光、流星、四季循环，页面与模型全部离线内置，歌曲能量映射到自转与云层转速。

**⑥ 街机合集（v2.39.17）——内嵌魂斗罗。** 自动 bot 驱动，无需遥控操作就能自己往下打，8 关全部可通关。调试过程很硬核：bot 从"60 万步卡第 7 关、934 次死亡"优化到"52,641 步走完 8 关、92 次死亡"，再降到"1.46 万步 / 11 死"。图形素材改用上游真图打成 1024×1024 图集（489 帧、约 56 KB），v2.39.18 起公开分发，成为公开版的第 27 套效果。

**顺带一提照片墙**：v2.39.18 一口气新增 33 种转场（视差滑动、希区柯克变焦、Voronoi 碎片化……），总数做到 76 种，然后又主动下线 6 个"拼块拼不回原图"的坏效果，**回退到 70 种**。另加了拍摄日期水印（切换完成后右下角显示红色时间戳），并修好了 NAS「家庭视频和照片」库扫不到照片的根因——相册级回退实测读到 2 万张。

## 二、音源治理：从"能连上"到"可控、可验证"

视觉效果之外，这三周最有工程价值的是把音乐源的管理理顺了。

- **洛雪音源（v2.39.8）**：可以在设置里导入第三方音源脚本，为网络歌曲找更高音质的播放直链；每个源支持一键验证可用性，逐平台显示能不能播、失败原因是什么。内置清单补齐为实测能播的 5 个源（原只有墨澜 / 星海）。修复了"点验证只闪一下没结果"——原来内置源出厂只有脚本地址没有正文，现在会先自动下载脚本再跑三级验证。
- **音乐源总开关（v2.39.8–v2.39.9）**：Meting / 百度网盘 / Jamendo / 本地 / NAS 各自可单独关闭。v2.39.9 把这个开关**真正做透了**——关闭后专辑、艺术家、歌曲、歌单、流派、年份、搜索结果、发现页、首页各区块、智能电台批次、"我的"页收藏全部按开关过滤，并且停止向该源发起任何请求，立即生效无需重启。这一串修复（关了网盘还能搜到网盘歌曲、关了 Jamendo 还加载热门……）看似琐碎，却是"开关"这个承诺能否兑现的关键。
- **一处命名澄清**：设置里的「网络搜索默认源」改名为「歌单与艺人数据源」，并写明真实作用——只影响歌单页 / 艺人页 / 封面匹配，搜索始终是各源并行后合并，不按"默认源"优先。这种"把 UI 文案改成和实际行为一致"的改动，我认为比加十个功能更有价值。

## 三、日常体验：主题、焦点与歌词

- **浅色主题（v2.39.6）**：主题设置改为跟随系统 / 深色 / 浅色三态；随后补了浅色下播放按钮、逐字歌词已唱部分、徽标的对比度，以及状态栏 / 导航栏底色跟随主题。
- **遥控器焦点（v2.39.6–v2.39.7）**：新增「焦点高亮」开关（默认开）。原来靠设备型号识别来判断"看不看得出焦点"，现在改为默认开启、手指点按自动收起、按方向键恢复，不再依赖机型。这一条来自真实用户反馈——有电视上用遥控器根本看不出焦点在哪一项。
- **K 歌全屏（v2.39.6）**：隐藏顶部导航栏，TV 与手机一致。
- **逐行歌词（v2.39.18）**：修了"逐行模式不跳行"——根因是 `derivedStateOf` 捕获了普通参数导致派生值永不重算；歌词分词也改为按码点切分，不再把 emoji / 组合字符 / 俄文从中间劈开。

## 四、稳定性与安全性：两轮全库审查

这三周还做了两轮彻底的代码审查，这是功能之外最重要的"隐形进展"：

- **v2.39.16：154 项发现一次性落地**（Critical 1 / High 13 / Medium 94 / Low 46）。最要命的 Critical 是相册转场在 API < 26 上用 `clipPath` 会把硬件渲染进程打崩，已统一降级到交叉淡化，并加了门禁测试守住红线。同批还修了 B 站 MV 直链没做主机白名单（响应被投毒时可把播放器指向任意地址，含 `file://` 与内网）、逐字歌词按 `String.length` 切分、播放服务换封面时旧 Bitmap 不回收等。
- **v2.39.18：审查 59 条终稿发现整改**。包括模型上传改为"临时文件 + 校验后原子替换"（原来失败会删掉已装好的模型）、下载半截音频不再误标"已完成"、飞牛曲库异常 total 时不再只加载第一页、Jellyfin 一条坏记录不再让整批歌曲变空、洛雪脚本的 302 跳转逐跳校验（防内网 / 云元数据 SSRF）。
- **真机兜底**：FLAC 在老电视上导致整进程崩溃 → 无损档自动降级为 320kbps 并弹一次说明；高质量人声分离在内存不足时立即提示并回退快速模式（v2.39.5 的起点）；日志里两类 E 级"假错误"（照片解码取消、IP 定位不可达）降级，避免真错误被 2 分钟的日志窗口挤没。

## 写在最后

回头看这三周，其实是一套挺典型的开源迭代节奏：**先做加法**——六个视觉世界、33 种转场，把"好看"这件事堆到极致；**再做减法**——千里江山推翻自创效果忠于上游、下线 6 个拼不回原图的转场，承认"少即是多"；**最后做加固**——两轮 213 项审查发现、各种降级与兜底，让它在老电视、小内存、烂网络上也能活着。

功能会被记住，但真正决定一个 TV 播放器能不能日常用的，往往是那些没人截图的东西：一次 FLAC 崩溃的降级、一个看不清的遥控器焦点、一条被降级的假报错。这三周，它们在 CHANGELOG 里占了比新效果更多的篇幅——我觉得这是好事。
