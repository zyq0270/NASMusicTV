## 〇·A 2026-10-28 裁定变更：放弃自绘几何，改为移植 `shan-shui-inf`

> **所有者原话**：「E50 的自绘效果很差，很难看，所以希望照抄移植 shan-shui-inf」。
> 这条裁定**推翻** v1.x 的技术底座（§3.1 的六层渐变带、§4.2 的有限傅里叶周期构造），
> 但**不推翻**配色（§3.3）、运动学（§4.3–4.6）、分帧烘焙（§7.3）、后处理三段式（§7.4）、
> 印章（§六）与门禁纪律（§八–§十一）。
> **v2.0 的唯一目标**：把「用代码模仿青绿山水」换成「把一幅已被验证好看的山水**搬**过来」。

### A.1 为什么这是对的（v1.x 失败的机制成因）

v1.x 前四轮把力气全花在**配色收敛**（§3.3 六族面积/中位、G8 色域门禁）。
但配色只回答「颜料对不对」，v1.x 从头到尾没有解决「**笔法**」：

| 项 | v1.x 实际做法（原型 `file:line`） | 后果 |
|---|---|---|
| 山体维度 | **1 条脊线** `ridgeY(x)` + 竖向渐变 `fillBand()`（`e50-qianli-jiangshan-preview.html:316-346`、`:240-251`） | 山只有剪影，没有体积 |
| 皴 | **同一条脊线的下移副本**：`dn=(0.10+0.55·i/(cun−1))·amp·2.2`、`lineWidth 1.6px`、α 0.05–0.10（`:347-355`） | 皴必然是**与山脊平行的 6 条等高线** ⇒ 读成矢量等高线，不是皴 |
| 边缘 | 无描边，`fillBand` 的平滑二次曲线（`:240-251`） | 边缘绝对光滑 ⇒ 塑料感 |
| 矾头 | `arc()` 正圆 + 径向渐变（`:356-367`） | 「飘在山脊外的一串球」（§十四 已记录，G8 量不到） |
| 植被 | **零**（原型全文 `texture` 关键词 **0 次**） | 山是裸的 |

⇒ **结论：v1.x 不是「颜色不对」，是「没有笔触层」。** 再调 100 轮配色也不会像。

### A.4 架构变更（一句话）

> **v1.x**：5 个**周期位图**按不同速度 `ImageShader(Repeated)` 平铺 → 1 op/层，但**会看出重复**。
> **v2.0**：每层 **N 个唯一分块**（默认 3：左/中/右）按层速度轮转 + 惰性再生成 → 1 blit/块/层，**永不重复**。

⚠️ 这条变更同时解决三件事：① **观感**（不重复）；② **内存**（不再需要 10 张全周期带，§7.2′）；
③ **保真**（`mountplanner` 的构图逻辑可原样搬，⛔ 不用再发明一套"怎么摆山"）。

⚠️ **代价（必须写进预算，⛔ 不许含糊）**：分块是**运行时**生成的，所以它把 v1.x 的
「一次烘焙、永远免费」变成了「**滚动到边界才生成**」。⇒ 必须证明**单块生成耗时 < 一帧预算**，
否则滚动会周期性卡顿。这条是 v2.0 的**头号风险**（§十二 R1），判据见 §8.2 的 **G15**。

## 一、为什么做这一套，以及它凭什么不与既有 27 套撞车

### 1.1 库里缺的两样东西

1. **运动语义缺"横向长卷流动"**。27 套里的运动主体要么是**单个物体**（E29 行星 / E35 光轴 / E42 星轨），
   要么是**原地介质**（E43 海浪 / E44 云与光柱 / E46 雾 / E47 雪 / E48 烟 / E49 鸟群）。
   ⛔ **没有一套的画面本体是"一整幅横向展开、多层以不同速度流动的长卷"**。
   E48 的沙丘是**静物**（只有烟和驼队动），E49 的视差只发生在**底部 1/5 的带**里（树带 ≈6 px/s）。
2. **色相族缺"矿物青绿 + 绢本暖底"**。现有冷蓝（E43/E47）、暖红（E48）、月白（E44）、深空（E41/E42）都有，
   ⛔ **石青 / 石绿 / 赭石 / 暖黄绢底**这一族一个都没占。它同时是本主题最不可让渡的识别度（需求 §3.2）。

⇒ 这两个缺口是同一件事的两面：**「一幅会动的青绿长卷」在本库里既是新运动，也是新颜色**。

### 1.2 ⛔ 与最近亲的区分点（三套必须"读起来不是同一张图"）

| | **E43 海边** | **E48 大漠孤烟** | **E49 鸟群掠过荒野** | **E50 千里江山（本主题）** |
|---|---|---|---|---|
| 主体运动 | 浪**向岸推进**（纵向） | **静物** + 一柱烟（纵向） | 群体**自组织**（横向、无序） | **多层长卷横向流动**（有序、匀速） |
| 画面是否整体位移 | ❌ 原地 | ❌ 原地 | ⚠️ 仅底部 1/5 带 | ✅ **全画面分层流动** |
| 色相族 | 冷蓝海水 | 饱和暖红 + 黑沙 | 暮色冷天 + 暖地 | ⭐ **青绿 + 暖黄绢底** |
| 有无发光天体 | 无 | ⭐ 低垂巨大落日 | ⛔ 刻意不画 | ⛔ **不画日盘、不画月** |
| 天空占比 | 上 1/2 | 上 3/5 | ⭐ 压倒性（>3/4） | 上 **0.42**（山占了中部） |
| 留白位置 | 浪与滩 | 沙丘与天 | 天空 | ⭐ **江水带 = 横向留白**（下部 0.38） |
| 第一读感 | 俯冲 / 湿 / 冷 | 热 / 静 / 竖 | 开阔 / 动 / 横 | **古 / 缓 / 横 / 纸本** |

⭐ **唯一关键区分点：本主题的画面本体是"一张平铺的画"，不是"一个场景"。**
其余全是推论 —— 因此三条硬性后果：

- ① 每一层都是**沿 X 无缝平铺的带**（§四），⛔ 不是"画面上摆几个山形"；
- ② 运动**匀速、无节奏性**（需求 §四.6 的 1.3× 上限就是这条的量化），⛔ 不跟鼓点走；
- ③ 质感来自**纸本**（绢纹 + 做旧 + 皴擦），⛔ 不来自光效 —— 这一条决定了 §七 的填充预算怎么花。

### 1.3 需求「频谱融入山水」在本仓的具体含义

需求的原话是"⛔ 不得出现传统突兀的柱状频谱条"。**本仓 27 套里其实早已没有裸柱状图**
（E05 圆环、E13 网格等是"频谱几何化"，不是柱）。本主题把这条推到底：

> **律动只作用于"材质参数"（透明度 / 平铺相位 / 色偏移 / 流速），⛔ 绝不作用于"几何轮廓"。**

⇒ 山体轮廓、水线、地平线**全是静态烘焙结果**；频谱改的只是**α、偏移、色温**。
这一刀切下去，"频谱破坏静谧意境"（需求 §十一.3）就没有物理发生的路径了。
这是本主题的**第一设计约束**（D5）。

## 三、画面构成：一条五层长卷

### 3.1′ 分块图层表（v2.0 —— ⛔ 取代 v1.x 的「六层渐变带」）

> ⛔ **v1.x 的图层表已作废**（每层一张周期位图 → 会看出重复，且山的几何是自绘的）。
> 不变的是**遮挡规则**：API 22 创维在 `Region::createTJunctionFreeRegion` 原生 SIGSEGV ⇒ 全仓红线
> （`docs/archive/blackhole-visualizer-plan.md §一（遮挡规则）`），**遮挡只由绘制顺序产生**，⛔ 不写任何裁切/遮罩代码。

变化的是**载体**：每层从「1 张周期位图」变成「**N 张唯一分块位图**」，滚动到边界时惰性再生成（§4.1′）。

| 序 | 层 | 载体（Kotlin） | 每帧 op | 分块数 | 频谱驱动 |
|---|---|---|---|---|---|
| L0 | **绢底天幕** | 全屏竖向渐变 + 绢纹 + 做旧（**v1.x 保留**，⛔ 不分块） | 1 | — | `sectionEnergy` 只改覆盖层 α |
| L1 | **远景** | `ShanShui.distMount()` 淡墨远山 + 远雾 | **N** | N | α / 速度 |
| L2 | **中景主山** | `ShanShui.mountain()`（青绿染色） | **N** | N | — |
| L2′ | **轮廓光** | `glint` 独立位图（⭐ 与 L2 **同种子同相位**，G10） | **N** | N | ✅ `mid` → α（**主"有音乐"信号**） |
| L3 | **近景** | `flatMount()` + `rock()` + 树 | **N** | N | ✅ 轻微 α |
| L4 | **江水** | `water()` 底纹 | **N** | N | ✅ 波幅 α |
| L4′ | **江水高光** | `water()` 高光丝 | **N** | N | ✅（LOW 档可省，见下） |
| L5 | **光尘** | 点阵**平铺**位图（v1.x 保留 —— 周期对细碎光点无害） | 1 | — | ✅ `treble` → α + 相位 |
| L6 | **grade** | 暗角 + 颗粒（三段式，同 E46–E49） | 1 | — | ❌ |
| L7 | **印章** | 朱砂印，屏幕固定坐标 | 1 | — | ❌ 恒定（§六.3） |

**图元账：`ops = 4 + 6N`**

| N | ops/帧 | 判定 |
|---|---|---|
| **2** | **16** | ✅ 进创维 60fps 模型（≤18） |
| 3 | **22** | ⚠️ 只能保 30fps 线 |
| 4 | 28 | ⛔ 不采用 |

⇒ **默认 `N = 2`**，每块宽 ≥ `1.05 × 屏宽`（保证"覆盖整屏时另一块可在后台重生"）。
⚠️ 这个 18 op 的门槛来自 v1.x §7.1 的真机线性模型（~0.41–0.47 ms/图元 + ~24.6 ms 固定成本），
而该模型**在"多小 op 合并成少大 blit"后会过预测**（E16 实测 44.1fps vs 模型 27fps）⇒ **必须按 §7.1′ 重测斜率**，⛔ 不许直接拿 16 当"够用"。

⚠️ L7 印章**必须画在 grade 之后**，否则暗角会把朱砂红一起压暗、四角不匀（D8）—— 这条**不变**。
⚠️ LOW 档省 L4′（−N op），但 α 照常计算（与 v1.x 同制，⛔ 不要连 α 一起省）。

### 3.2 构图锚点（⛔ 全部归一化，不写死 px）

```
skyTopY      = 0.00H                     // 绢底最上：偏冷的青灰
horizonY     = 0.620H                    // 江面顶界 —— ⭐ 本主题的"留白"从这里开始
waterBottomY = 1.00H                     // 江水带 = 底部 0.38H
farRidgeY    = 0.42H … 0.58H             // 远景峦头只露在山脊以上
midPeakY     = 0.20H … 0.55H             // 中景主峰（画面的重心，青绿最饱和处）
nearFootY    = 0.66H … 0.88H             // 近景坡石，压在江水带之上、只占底部
sealCenter   = (W − inset − s/2, inset + s/2)   // 右上角，s 见 §六.3
```

- ⭐ **江水是"横向留白"**：中部偏下必须有一条**基本空着**的亮带，这是长卷读感的来源。
  ⛔ 不许把山铺满到这里（需求 §3.3「保留适量留白和云雾，不能满屏堆满山体」的量化落点）。
- ⛔ **地平线不是一条尺子线**：与 E49 相反（E49 的干净直线是"远景"读感来源）。
  本主题的江岸是**软过渡**（波纹与坡石交错），由 L3/L4 两层自身形状给出，不画线。
- **山峦必须"层峦叠嶂"**：远/中/近**三层都必须各自有内部起伏**（同层内 ≥2 次谐波），
  ⛔ 不能是"三个高度的三角波"（= 需求禁止的卡通扁平山水）。

远山 = 青/绿**亮锚** + 整带绢色罩纱；近坡 = 绿深 → 赭深 → **墨中位锚收脚**（⛔ 不用墨深锚，见下）。

⭐ **中山站表必须按「渐变坐标」而非「画面坐标」排**（本轮实测踩到，K4 必须照抄）：

- ① **色相族**：每条渐变每一站须落在 `h∈[15°,95°]`（暖/赭/墨/水）**或** `h∈[140°,215°]`（青绿）内。

  三段链（170→35 天然跳 135°），却放得过旧版那套灰蓝 —— ΔH 咬"相邻差"，对"通体灰青"完全盲。
  ⚠️ ① 只判**声明站**；罩纱/混合后的合成像素允许落在低饱和过渡带，由 ② 的下限和 ③ 兜住。
- ② **分位**（非印区、每 7 像素等距抽样）：`S p50 ∈[0.18,0.42]`（参考 0.298）、
  `L p50 ∈[0.32,0.50]`（参考 0.410）、`L p95 ≤ 0.62`（参考 0.516 —— 旧版爆白实测 0.788 就是被它抓住的）、
  `S p99 ≤ 0.70`（参考 0.626，容矿物色峰）。⛔ 不设 `L p05` 下限：暗角（墨深锚 α 0.10）压在四角，
  合法最暗部本来就比参考图的 p05 低一档，设下限会逼着把暗角关掉。
- ③ **高饱和端**（S ≥ 本图 p95）的色相仍须落在 ① 的两族内，例外 ≤ 5%（②管平均，③才咬局部爆色）。

- ⑤ **负对照**：族谓词必须**拒绝**紫/洋红/靛/橙红四个已知错色，否则判据恒真也算通过 = 无判据。
- ✅ 频谱光效低亮度、半透明：光晕层 `α ≤ 0.34`、光尘 `α ≤ 0.22`。

### 3.4 ⛔ 卡通 / 霓虹 / 炫技的负面清单（需求 §十一 八条 → 本仓可判读形式）

1. ⛔ **不画日盘、不画月**（撞 E48 / E44）；⛔ 不画雪（撞 E47）；⛔ 不画鸟群（撞 E49）。
2. ⛔ **山体轮廓不因频谱形变**（需求 §四.10 的落实 = D5：几何在烘焙期定稿，逐帧只改 α/偏移）。
3. ⛔ **不出现任何柱状/环形/线形均衡器几何**；⛔ **不读 `frame.spectrum` 数组**（见 §五.3）。
4. ⛔ **不用纯白/纯青的"发光"叠加**：轮廓光晕只有一种色 = **赭石亮锚 `#A97D40`**（§3.3，
   旧名"淡金"），光晕 `α ≤ 0.34`、光尘 `α ≤ 0.22`。
   ⚠️ 判据不是"感觉太亮"：参考切片**全图 L p95 只有 0.516**，真迹里没有近白 ⇒
   旧版 `rgba(250,244,226)`（波纹高光）与 `rgba(241,236,220)`（云气）这类 L 0.85+ 的高光
   全部是编的，单是把整条地平线洗白（实测江面带 L 0.79）。现在两端一律取实测亮锚。
5. ⛔ **不做粒子系统**（无 `ParticlePool`）；光尘是平铺位图，⛔ 逐粒小 blit（该形态正是 P-3 崩溃的触发形状）。
6. ⛔ **不加厚重描边**：皴法是烘焙期一次性烘进位图的**低对比纹理**，不是逐帧 stroke。
7. ⛔ **不做逐帧 `createLinearGradient`**（全仓红线，E43 已把它折成一条缓存渐变/烘焙位图）⇒ 五层渐变**全部烘进位图**。
8. ⛔ **画面不闪、不抖、不弹跳**：任何 α 变化必须过 `AudioSmoother`，且 attack 慢（§五.4）。
9. ⛔ **不用「单条平滑脊线 + 竖向渐变」画山** —— 这是 v1.x 被判"很难看"的直接形态（§〇·A.1）。
   山体必须是 `mountain()` 的**多行点阵**（`reso=[10,50]`），且**必须有笔触层**。
10. ⛔ **皴线不得与山脊平行** —— v1.x 的 6 条「脊线下移副本」是**等高线**，不是皴。判据见 **G14**。
11. ⛔ **矾头不得是正圆** —— v1.x 的 `arc()` 画出「飘在山脊外的一串球」（§十四 第 4 轮已记录，G8 量不到）。
    改用 `blob()` 的**纺锤笔触点**。
12. ⛔ **最终交付不得是上游的灰阶配色**（`rgba(100,100,100,α)`，`mountain():1858`）。
    ⚠️ 但 **V-A（灰阶）是合法的对照组**（D17/§3.6.5）—— 它用来证明"几何本身是对的"。
    ⇒ 准确口径是：**V-A 可以存在，但不能是最终选定的那一版**；最终版必须按 §3.3 染色（V-B 或 V-C）。

### 3.5 多画幅与竖屏（⛔ 只做一套构图）

需求 §3.3 要适配 16:9 / 18:9 / 20:9 / 4:3。本主题的锚点**纵向按 `H` 取比例、横向周期按 `W` 取比例**
（`RenderContext.kt` 的 `canvasSize` 是**像素**，`minDim` 已提供短边基准），因此：

- 20:9（更宽）⇒ 同一时刻看到长卷的**更多**内容，滚动线速度不变（⛔ 不按 W 缩放速度，否则宽屏变快）；
- 4:3（更接近方）⇒ 看到**更少**内容，中部主峰仍完整；
- **手机竖屏**（`MainActivity` 是 `fullSensor`，必须能看）⇒ 纵向比例锚点自动把画面读成
  "上下留绢底、中间一条青绿山"，⛔ **不做第二套竖屏构图**（两套构图 = 两套数字 = 两份偏差）。

> ⚠️ 由既有真机教训：**「手机对、电视错」时差异不可能来自几何**（`DrawScope.size` 是像素，
> 两台设备 `minDim` 都是 1080）⇒ 若真机上出现只有电视不对的现象，去查 §四.2 的**绘制机制**，
> 不要重推 dp/density。

#### 3.6.3 必须**改造**而不能照搬的四处（这才是移植的真实工作量）

1. **SVG 字符串 → `Path`。** `poly()`(:485-510) 返回 `<polyline points='…'>` 字符串；
   Kotlin 侧直接累积 `Path` + `Paint`。⛔ 不做字符串中间层 —— 单块上千个点，字符串拼接是纯浪费。
   ⭐ 改造面**只有 3 个函数**（`poly`/`stroke`/`texture`，见 3.6.1 末注），其余生成器原样搬。
2. ⭐ **PRNG：把 `Prng` 原样搬，⛔ 不要换 `mulberry32`。**
   上游在 `:54-56` **全局覆写** `Math.random = () => Prng.next()` ⇒ 全文 **155 处 `Math.random()` 调用点全部已走种子流**，
   调用次序天然与上游一致 —— 我们**一行调用点都不用改**，只提供 `rnd()`。
   ⛔ **换 `mulberry32` 的代价**：序列不同 ⇒ 山形不同 ⇒ **再也无法与浏览器对账**（G4/G13′ 只剩"自己跟自己一致"，
   证明不了"照抄了"）。⇒ **D15 已按此改判**。
   ⚠️ **三个必须踩准的坑**：
   - `hash(x)` = `btoa(JSON.stringify(x))` 的字符按 `charCode·128^i` 累加 ⇒ **溢出 2^53**（实测 `hash(1234) = 3.4610482573896268e16`）。
     ⇒ Kotlin 必须用 **`Double`** 累加、**按下标升序、逐项 `+`**；⛔ 用 `Long`/`BigInteger`（值不同）、⛔ 改写成 Horner 形式（舍入不同）。
   - `next()` 的 `s = s² mod m`：`s` 可达 1e12、`s²` 可达 1e24，**同样溢出 2^53** ⇒ 依然只能 `Double`。
   - `seed(x)` 末尾**预热 10 次 `next()`**（`:30-32`）⇒ 漏掉这 10 次，整条序列错位。
   ✅ **已实测可逐位复现**：`logs_temp/prng_check.js`（node v24.13.1）与 `logs_temp/prng_kotlin_equiv.py`（IEEE-754 double 等价实现）
   在 `num:1234` / `str:1234` / `num:7` 三例上 **hash、`sAfterSeed`、前 8 个输出全部逐位相等**（`RESULT: PASS`）。
   黄金向量（seed=`1234`，数值型）：`sAfterSeed = 334869857393`，
   前 4 个输出 `0.5179214018993742 / 0.19101042199684515 / 0.1481747547047804 / 0.8586372206878526`。
   ⚠️ 注意 **`seed(1234)` 与 `seed("1234")` 不同**（`JSON.stringify` 给出 `1234` vs `"1234"` ⇒ base64 不同 ⇒ 种子不同）。
3. **`Noise` → Kotlin**：约 87 行逐行搬（见 3.6.1 末行）。⚠️ `Noise.noiseSeed()` 与 `Prng` 是**两套独立**的种子系统，⛔ 不要合并。
4. **无限流 → 分块位图**：见 §4.1′。⚠️ 上游 `MEM.cwid = 512`、视口 `3000×800`；我们的块宽是 `≥1.05×屏宽`（约 2016 px），
   比上游的 512 大得多 ⇒ **单块生成耗时也按比例更大**（R1 的直接来源）。

- **非凸 Path 只在烘焙期画。** `stroke()` 的 ribbon 与 `mountain()` 的坡面填充都是**非凸、可能自交**的多边形。
  E46 真机定位：`concat` × 非凸 ⇒ **80 帧 0 像素**（`TripodFillMechanismGateTest` 守）。
  ⇒ 全部在**烘焙期**画进位图，逐帧只 blit。⛔ 不要"顺手"改成逐帧画。

**V-B / V-C 的染法硬约束（仍然有效）**

- **按坡段取色，⛔ 按 y 取色。** 颜色由该笔触在坡面点阵里的**行号 j** 决定（`j=0` 山脊 → `j=R` 山脚）。
  这正是 §3.3 ⚠️ 条「站表必须按渐变坐标排」的**根治**：v1.x 只能按 y 排，因为山只有一条脊线。
- **每个笔触一次取色，⛔ 不在位图上叠全帧色层。** 染色发生在 `stroke()/poly()` 的 `col` 参数上；
  叠一层色相覆盖层会把皴的干湿变化一起洗平（= 又退回 v1.x 的"一块色"）。
  ⚠️ **V-C 的"平涂"不违反这条**：它是**坡面多边形的 `fill`**，画在皴**之前**、仍在烘焙期，
  不是全帧覆盖层，也不洗掉任何笔触。
- **上游的 `white` 必须换掉。** 它用于叶簇与水花（`:17` 次），在青绿底上会读成**荧光白点**（撞 §3.4-8）
  ⇒ 改**绢白 / 淡青**。⚠️ 这一条只对 V-B/V-C 成立，V-A 保持原样。

**判读后的收口**：三版并排交给所有者，**一次定案**。⛔ 不要出现"V-B 与 V-C 各取一半再调"——
那等于又回到 v1.x 那种"凭感觉改配色"的循环（§〇·A.1 的成因就是它）。

## 四、长卷滚动与分块流（v2.0 核心）

### 4.1′ 分块轮转（⛔ 取代 v1.x 的 `ImageShader(Repeated)` 平铺）

> 上游 `shan-shui-inf` 的「无限」是 **惰性分块流**：`chunkloader()` 在可视窗口 ±`MEM.cwid` 内现场生成
> 唯一 chunk，`chunkrender()` 拼接（`index.html:3845-3894`、`:3973-3984`）。
> ⛔ **它没有周期 `W`，也没有接缝问题** —— 每个 chunk 都不一样。

Kotlin 侧不能拼 SVG 字符串，改拼**位图块**：

```
每层维护一个 ring buffer: blocks[0..N-1]，每块 = 一张 Bitmap + 世界坐标 x0
逐帧：offset += v_layer · dt
      当某块右缘 < 视口左缘 ⇒ 该块作废，重新生成到最右侧（x0 += N·Wb）
      绘制：for b in blocks: canvas.drawBitmap(b.bmp, b.x0 − offset, y0·H, paint)
```

- **块宽 `Wb ≥ 1.05 × 屏宽`** ⇒ 任一时刻「覆盖整屏」与「另一块在后台重生」可以并存，⛔ 不出现空白。
- **N = 2**（§3.1′ 的 ops 账）⇒ 视口内永远只有 2 个唯一块，**重复周期 = 2 屏**，
  远大于 v1.x 的 `1.0–2.0 屏` ⇒ 观感上是"不重复"。
- ⛔⛔ **位移绝不靠 `Shader.setLocalMatrix`**：E43 真机实测在硬件画布上**静默失效**（画了个不偏移的）。
  ⇒ 一律走 `drawBitmap(bmp, x, y, paint)` 的 x 参数（或 `canvas.translate`），⛔ 不留 local matrix 代码。
- ⚠️ `drawIntoCanvas { }` 里成对 `save/restore`（⛔ 逐图元 `save/restore`，E48 红线）。
- ⚠️ **块高 = 层带高**，⛔ 不是全屏（远景只占 0.46H，见 §3.2）。⇒ 每块内存 = `Wb × bandH × 4`。

**重生必须与渲染解耦**（本方案头号风险 R1）：

- ⛔ 不许在 `draw()` 里同步生成一块（单块 2,400 行 JS 的等价 Kotlin 工作不可能塞进 16ms）。
- ✅ 采用 **`bootPending` 同族的两段式**（§7.3 已有一套）：`draw()` 只置 `pending` 标志，
  生成在**后续帧的预算片**里推进（每帧最多 `BLOCK_BUDGET_MS`），生成完成前该块**画上一轮的旧块**
  （旧块内容不同但风格一致 ⇒ 读作"山在变"而不是"空白"）。
- ⚠️ 若预算内做不完，**降级顺序**：先砍 `rock`/`hut` 装饰 → 再砍 `tree` → 最后才降块宽。
  ⛔ 不许"生成失败就画空白"（用户读成黑屏）。

### 4.2′ 接缝：从"数学闭合"退化为"块间风格一致"

⛔ **v1.x 的 G1/G2（周期闭合、相位对账）整节作废** —— 分块流没有周期，接缝根本不存在。

但换来了一个新的失败模式：**相邻两块画风不一致**（例如一块树多、一块树少、或山脊高度突变）。
⇒ 判据改为 **G1′ 块间连续性**（§8.2）：

- 取任意相邻两块在接缝处的**同一行**，比较「该行不透明像素的左/右延伸长度」与「平均明度」，
  两者之差 ≤ 内部同类位置的 p90（⛔ 不设绝对阈值 —— 阈值必须由 harness 再生）。
- ⭐ 更本质的一条：`mountplanner` 是**连续扫描**的（`xstep=5`，`MEM.planmtx` 记录占位），
  只要 `xmin/xmax` 首尾相接，**构图本身天然连续** ⇒ 块间不一致只可能来自 **PRNG 被重置**。
  ⇒ **G4′ 判据**：块 k 的生成必须用 `seed(base + k)` 的**连续流**，⛔ 不许每块 `seed(固定值)`。

### 4.1-旧 ⛔ v1.x 作废（保留仅作历史追溯）：平铺机制

选定与 E48「贴地浮沙带」**完全同形制**的做法：单层画笔 = `ShaderBrush(ImageShader(bmp, Repeated, Clamp))`
（X 向 `Repeated` 无缝循环、Y 向 `Clamp` 不外溢），逐帧只走**一次画布平移 + 一次 `drawRect`** ⇒ **1 op/层**。
参考：`DesertSmokeRenderer.kt:787-789`、`:614-621`（原型的"平铺第二张补右缘"在 Kotlin 侧被折叠成 1 op）。

- ⛔ **不用"两张位图来回 blit"**：那是 2 op/层，且右缘补缝逻辑在多周期下极易错（E48 已在原型里用第二张补缝，Kotlin 侧专门折叠掉）。
- ⛔⛔ **位移绝不靠 `Shader.setLocalMatrix`**：E43 真机实测在硬件画布上**静默失效**（画了个不偏移的），
  修法是把映射移到 **Canvas 变换**里 ⇒ 本套所有滚动一律 `canvas.translate`，⛔ 不留任何 local matrix 代码。
- ⚠️ 平铺 + 平移的画布必须在 `drawIntoCanvas { }` 里成对 `save/restore`（⛔ 逐图元 `save/restore`，E48 已列为红线：一次帧内多次 save/restore 是成本项）。
- ⭐ **平铺的锚点与缩放必须显式做**（2026-10-18 原型现场补，门禁 G12 判这三件事）：
  位图平铺的原点是**当前画布变换的原点**，不是 `drawRect` 的左上角。所以每层必须
  ① `canvas.translate(-offsetPx, y0·H)` 把 **tile 第 0 行钉在带区上沿**（只平移 x ⇒ 整个山形上移 `y0·H`、
  且在设备行 `tileH` 处**纵向重复一次**，山脚被切出一条水平台阶——原型里真实发生过，G1/G2 只量 tile 自身，抓不到它）；
  ② `canvas.scale(1/sc, 1/sc)` 把 LOW/MEDIUM 的低分辨率烘焙**放大回显示尺寸**（§7.2 缓解项⑤"LOW 档 W/2 降采样"的前提）；
  ③ 缩放后用户单位就是 tile 像素，矩形高度取**位图自身高度 `bmp.height`（整格，整数）**，
  ⛔ 不取 `(y1−y0)·H·sc` 的浮点值 —— LOW 档实测 302.4 vs 位图 302 行 ⇒ 多画 0.4 格，
  等于把**下一格副本的第 0 行**叠进带底（原型 G12 在 LOW 档量到的"2 段"就是这么来的）。
  带区显示高度 = `bmp.height / sc`，与 `(y1−y0)·H` 之差 ≤1 设备像素（H2/G12 各有一条断言钉住）。
  三者合一后 Y 向 `Clamp` 才成立（带区恰好一个 tile 高，外溢无从发生）。

### 4.2-旧 ⛔ v1.x 作废（保留仅作历史追溯）：周期闭合构造

> 接缝不是靠"调参调到看不出来"，而是靠**轮廓函数在数学上以 W 为周期** ⇒ `f(0) ≡ f(W)` 恒成立。

**峰脊线**（每层一条）：

```
ridge(x) = base + Σ_{k=1..K} A_k · sin(2π k x / W + φ_k)      // ⭐ 有限傅里叶级数
A_k ∝ k^(-1.4)   (1/f 地貌感),   φ_k 来自 VisualizerRandom（固定种子）
```

- ⛔ **禁止任何非周期项**进入横向坐标：连续值噪声、随机游走、累积 `+= rng` —— 它们必然在 `x=W` 处不闭合。
  （这是需求 §四.4「接缝必须无缝、不得出现明显跳变」唯一可靠的实现路径。）
- **皴法纹理 / 矾头 / 矶石 / 波纹 / 光尘点阵**：用**周期化 value noise** —— 格点索引 `mod N`
  （⭐ 原型定稿的写法是 `u = (x / W) · N`，`N` = **一个周期内的格数**（整数），格宽 `W/N` **不必整除**；
   Kotlin 侧必须同形制，⛔ 不要写成 `floor(x / cellW)` —— 那种写法在 `W` 不整除格宽时**在缝上露馅**，H3 已把这条钉住）
  ⇒ 平铺接缝**像素级相等**。随机点位一律按 `x mod W` 落位，⛔ 允许越界的点必须在**烘焙期**复制成两份补缝
  （⛔ 不在逐帧画的时候处理）。

**门禁 G-seam（= 原型 G1/G12，两侧都判、可复跑）**：
1. `ridge(0) == ridge(W)`（相对误差 ≤ 1e-6）；
2. 一阶差分在接缝处连续：`ridge(W) - ridge(W-ε) == ridge(ε) - ridge(-ε)`（同一斜率，容差内）；
3. **机制判据（G1a）**：同一周期图平移 `P/2` 再切一张 tile ⇒ `tile2[列 c] ≡ tile1[列 (c+P/2) mod P]`
   **山体本体逐字节相等**（内部列差必须为 0；两张 tile 各自的**边界列**豁免，实测 ≤16 字节、单行 α ≤16 LSB）。
   ⛔ 不判"最左列 ≡ 最右列"（那是要求函数在缝处持平，不是平铺接缝的判据）；
   ⛔ 也不用"两周期宽的参照图"（改变路径总长 ⇒ AA 分块噪声 ±1 LSB 铺满 2.3% 列，真缺陷被淹没）。
4. **外观判据（G1b）**：把 tile 平铺两次，接缝那一列"跳变 ≥16 LSB 的行数"与"最大跳变"都 **≤ 内部最坏列**
   （单看 max 会把"接缝和笔触一样陡"误判成合格 —— MEDIUM 实测接缝 max 128 / 内部 max 167）。
5. **锚点判据（G12）**：blit 后 tile 第 0 行贴在**带区上沿**、带内**不纵向重复**、显示按 `1/sc` 放大；
   矩形高度取**位图自身高度**（整格），⛔ 不用带高浮点值（LOW 档会多画 0.4 格 ⇒ 下一格副本的第 0 行叠进带底）。

### 4.3 分层速度表（⭐ 实测值，由 `e50_scroll_harness.js` 的 H4/H2 再生）

需求 §四.5 给的区间取**中段偏慢**（"缓慢悠远"优先）：

| 层 | 线速度 @1080p（px/s） | 需求区间 | 周期 `W`（× 屏宽） | 单圈时长（实测 1920 宽） |
|---|---|---|---|---|
| L1 远景山峦 | **4** | 3–6 ✅ | `1.5 W` = 2880 | 2880/4 = 720s ≈ **12.0 min** |
| L1 雾带 | 6 | — | `1.0 W` = 1920 | 320s ≈ **5.3 min** |
| L2 中景峦头 + L2 光晕 | **10** | 8–15 ✅（同层同速，⚠️ **必须同速**） | `2.0 W` = 3840 | 384s ≈ **6.4 min** |
| L3 近景坡石 | **22** | 18–30 ✅ | `1.25 W` = 2400 | 109s ≈ **1.8 min** |
| L4 江水波纹 | 14 | —（水在中近之间） | `1.0 W` = 1920 | 137s ≈ **2.3 min** |
| L5 光尘 | 3（+ 高频相位偏移） | — | `1.0 W` = 1920 | 640s ≈ **10.7 min** |

H4 另测得：**比例 1.00 : 2.50 : 5.50**（目标 1:2.5:5.5 ✅）、限速上界 **1.30×**、
最大单帧位移 0.428px ≤ 理论上限 0.477px（near 22px·s⁻¹×1.30/60）。

⚠️ **同层必须同速**：L2 的山与它的轮廓光晕**必须严格同速、同相位**，否则轮廓光会脱离山脊滑走
（这是本主题最容易在真机上暴露的第一类缺陷：光晕"游"到半空）。⇒ 单测判据：`offset_mid == offset_glint` 恒等。

⚠️ **烘焙位图的真实成本是内存不是速度**：`W` 越大越看不出重复，但位图越长。位图只覆盖**各自的带高**
（远景层不是全屏高，只是山脊带 ≈0.46H）⇒ 内存账见 §七.2，**已实测：HIGH 51.96 MiB 破线**。
⭐ 优先级（与 §7.2 缓解表同一口径）：**先叠 ①（L0/grade 改 `RGB_565`）+ ②（L2 光晕降 0.5×）** ⇒ 37.41 MiB 进容差；
⛔ 不要动**带绢纹的层**（远山/中山/近坡）的分辨率——绢纹一糊就读成"扫描件"。
② 之所以合法：光晕层是**低频发光**（没有绢纹、没有硬边），降采样后运行时放大看不出差异。
缩 `W`（③）单独不够（47.53 > 46），且会缩短单圈时长（越短越容易看出重复）⇒ 排在最后。⇒ 开放项 **O6** 待裁。

### 4.4 音乐只允许"轻微推一把"

```
v_layer(eff) = v_layer(base) · (1 + 0.30 · energyS)     // 上限恰为需求 §四.6 的 1.3×
```

- `energyS` = `AudioFrame.energy` 经 `AudioSmoother`（§五.4）；⛔ **不用 `beat`**（鼓点 ⇒ 瞬间跳速 ⇒ 破坏悠远）；
- ⛔ 不用 `frame.spectrum`；⛔ 各层共用同一个 `energyS` ⇒ 层间**速度比恒定**（比例被破坏 = 视差穿帮）；
- 静音时 `energyS → 0` ⇒ 速度自动回到 base，⛔ 绝不停滞。

### 4.5 整体呼吸 1–3%

需求 §5.3「画面轻微呼吸，幅度 1%–3%」。落实方式：

- **⛔ 不用全屏缩放 redraw**（会重新经过所有层）；用**各层 `dstRect` 上下沿微扩**或 `canvas.scale` 于位图 blit。
- ✅ `canvas.scale` + **矩形/凸四边形 blit** 在 API 22 真机是**活的**（E43 线性渐变 + `setLocalMatrix`… 已改；
  concat + 凸四顶点实测 alive 2026-10-13）。
- ⛔ **绝不 `canvas.concat` × 非凸/自交填充路径** —— 同一 34 顶点多边形，屏幕空间 80 帧全填、
  经 `concat(axisMatrix)` **80 帧 0 像素**（E46 真机定位，`TripodFillMechanismGateTest` 守）。
  ⇒ 本主题逐帧**不画任何非凸 Path**，全部是位图 blit，天然避开该陷阱；几何复杂度都放在烘焙期。
- 驱动：`sectionEnergy`（8s 滑动均值）+ `pulse`，`scale ∈ [1.000, 1.030]`，⛔ 不乘 `bass`。

### 4.6 时间与生命周期（照抄既有铁律）

- **时间只有一个自变量 `tSec`**（由 `fx.dt` 累加），⛔ 不是 `ctx.nowMs`、⛔ 不是墙钟（E48 同律）。
  ⚠️ `fx.dt` 本身已是秒，⛔ 不再除 1000（E44 偏差 D31）。
- ⛔ 渲染器**不写生命周期代码**：舞台 `onPause` 停帧 ⇒ 滚动与音频自然停；恢复即续（需求 §四.8、§九.10 由架构满足）。
- ⚠️ **画质变化会重入 `onEnter`（不经过 `onExit`）** ⇒ `onEnter` 首行必须 `releaseAll()`（E48 逐字留过此痕）。
- 位图活在 API 22–25 的 **native heap** ⇒ 每张烘焙位图必须进 `onExit`/`releaseAll` 的释放路径。

## 五、频谱 → 山水的映射

### 5.1 通道来源（⛔ 只用律动通道）

| 视觉量（层） | 音频源 | 变化区间 | 说明 |
|---|---|---|---|
| L1 雾带 α 与流速 | `bass`（20–250Hz，`BASS_END=39`） | α `0.10 → 0.30`；流速 `×1.0 → ×1.3` | 低频只推**雾和水**，⛔ 不推山 |
| L4 江水波幅 α | `bass` | `0.16 → 0.34` | 与雾**同源不同曲线**（水响应快于雾） |
| L2 轮廓淡金光晕 α | `mid`（250Hz–3kHz，`MID_END=55`） | **`0.10 → 0.34`** | ⭐ 本主题唯一"发光"通道，也是最主要的"有音乐"信号 |
| L2 青绿饱和偏移 | `mid` | `ΔS ≤ 0.06`、ΔH ≤ 4° | 靠一张**饱和覆盖层**的 α 实现，⛔ 不逐帧重烘 |
| L3 近景雾气 α | `mid` | `0.06 → 0.16` | 需求「山脚雾气亮度」的落点 |
| L5 光尘 α + 平铺相位 | `treble`（3k–20kHz） | α `0.05 → 0.22`；相位 ±40px | 需求「细碎光点」落点；⛔ 飞鸟（撞 E49，见 O2） |
| 各层速度 | `energy`（≤1.3×，§4.4） | — | — |
| L0 冷暖 / 做旧强度 | `sectionEnergy`（8s 均值） | 色温 ≤ 2 单位；颗粒 α `0.026 → 0.034` | "段落响度决定画面情绪"，无节奏性 |
| 整体呼吸 | `sectionEnergy` + `pulse` | scale `1.000 → 1.030`（§4.5） | — |

### 5.2 为什么这套映射"读起来不像频谱"

因为**没有一条映射通向几何**（D5）。频谱能改变的只有**透明度、平铺相位、色偏移、流速**四种量，
而这四种量的变化上限都被压到"盯着看才发现刚才亮了一点"的量级 —— 需求 §5.1「以融入山水的方式呈现」的实现学定义就是这句。

### 5.3 ⛔ 不读 `frame.spectrum`（D5 的技术面）

`AudioFrame.spectrum`（64 柱，已 gamma 压缩）是**显示通道**。本主题一条都不读：

- 拿它画任何东西 ⇒ 必然出现"64 个随频率排列的几何体" = 柱状频谱换了个方向（需求 §5.1 禁止项）；
- 拿它驱动律动 ⇒ 强弱差异被 `DISPLAY_GAMMA = 0.75` 压扁（历史 BUG ⑨-b，`AudioFrame.kt` 类头明写「二者不可混用」）。

⇒ 律动只用 `bass / mid / treble / energy / sectionEnergy / pulse`，
需要"鼓点强弱差异"时才用 `bassRaw`（本主题**不需要**，因为⛔ 不跟拍）。
⚠️ 这条要写进门禁（G-通道：源码扫描渲染器，出现 `frame.spectrum` / `.spectrum[` 即失败）。

### 5.4 平滑：attack 慢、release 更慢（与烟花类相反）

既有 `AudioSmoother(attack, release)` 默认 `0.35 / 0.06`（"鼓点要快 attack"）。本主题**刻意改慢**：

```
雾 / 水 / 速度：attack 0.10  release 0.035     // 几帧才见得起势，落得更慢
淡金光晕    ：attack 0.18  release 0.05      // 唯一允许稍快的一路（"有音乐"的主信号）
光尘        ：attack 0.24  release 0.07      // 最亮的一路，但仍⛔ 不用 0.35 以上
段落 / 呼吸 ：attack 0.04  release 0.02      // 情绪级，几乎无感
```

判据（进 G-平滑）：**连续 60 帧内任一 α 的单帧变化量 ≤ 其总动态范围的 6%** ⇒ 物理上排除了频闪。

### 5.5 无音频时的优雅降级（需求 §八.2/§八.4 → 现状即满足）

- 停止播放/无音轨时分析层仍在输出 `pulse`（快起慢落脉冲）与呼吸；本主题以它作**降级动画源**
  （与 E42 星空「静音不全黑」同一路子）。
- **α 下限表**（⛔ 任何通道不得把对应层降到 0）：
  `L1 雾 ≥ 0.10`、`L2 光晕 ≥ 0.10`、`L4 水 ≥ 0.16`、`L5 光尘 ≥ 0.05`、`L0/L2/L3 山体 ≡ 1.0`。
  ⇒ 静音画面 = 一条缓缓流动、带极淡金光的青绿长卷。
- ⛔ 不弹权限框、⛔ 不报错、⛔ 不黑屏 —— 因为本主题**根本没有音频输入这条路**（裁定 5），
  需求 §八.4 的"降级"在本仓是**默认态**。

### 7.4 后处理三段式（必须照做，否则白补一次全屏 drawRect）

- `postFx` 留**字面量**当门禁证据 + `vignetteOverride` 恒 `0f` 关断基类绘制（暗角/颗粒由 grade 位图承担）；
- ⛔ **绝不退回 `PostFx.NONE`**：`NONE` 让 `hasFullScreenPass()` 恒假 ⇒ `RendererFx.needsDamageCoalescer`
  在 LITE/FULL **也为真** ⇒ 每帧多一次**整画布** `drawRect`（肉眼不可见、铺屏 1.000 屏）。
  E46 踩过两次、E47 逐字抄错再踩一次（`FxCoverageScanTest.kt:58-66` 留痕）；
- 新渲染器必须**同步登记进 `FxCoverageScanTest` 的 `covered`**（`FxCoverageScanTest.kt:41`）；
  名单 stale 判据会抓"文件存在但名单缺失"。
- ✅ 本主题 L0 本身就是全屏 blit ⇒ **天然满足"每帧至少一个全屏 op"**（P-3 原生 SIGSEGV 的规避条件）。

### 7.5 fps 目标（⛔ 与需求 §九.9 不同）
